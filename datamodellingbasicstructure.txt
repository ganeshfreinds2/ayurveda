To develop a mobile app for Ayurveda and home remedies based on Rajiv Dixit’s teachings, we need a PostgreSQL data model that supports user-entered health problems, remedies, videos, articles, and personalized recommendations. The data model will use **chunks** (via PostgreSQL partitioning for scalability) and **vectors** (using the `pgvector` extension for semantic similarity in recommendations). The model excludes pharmaceutical integration, focusing on remedies, user problems, and recommendations. Below, I provide a single SQL script to create the data model, including tables, indexes, partitioning, and vector support, ready to execute in PostgreSQL.

### Key Requirements
1. **Core Features**:
   - Store remedies, videos, articles, user accounts, and user-entered problems.
   - Provide personalized remedy recommendations based on user problems, preferences, and interactions.
   - Include a disclaimer in metadata.
2. **Scalability with Chunks**:
   - Use PostgreSQL partitioning to split large tables (e.g., `User_Interactions`, `Recommendations`) into chunks for performance.
3. **Vector-Based Recommendations**:
   - Use `pgvector` to store embeddings for remedies and user problems.
   - Compute semantic similarity between problem descriptions and remedy descriptions for recommendations.
4. **Exclusions**:
   - No pharmaceutical products or remedy-product links.

### Prerequisites
- **PostgreSQL**: Version 14 or later (supports `pgvector`).
- **pgvector Extension**: Install via:
  ```bash
  CREATE EXTENSION vector;
  ```
- **Partitioning**: PostgreSQL natively supports table partitioning.

### Data Model Design
The data model includes tables for users, user problems, remedies, videos, articles, interactions, recommendations, and metadata. Key features:
- **Partitioning**: Applied to `User_Interactions` and `Recommendations` for scalability.
- **Vectors**: Store embeddings in `Remedies` and `User_Problems` for semantic similarity.
- **Indexes**: Use GIN for JSONB and vector indexes for embeddings.
- **Recommendations**: Combine vector similarity (for problem-remedy matching) with content-based filtering (tags, categories).

```sql
-- Enable pgvector extension

    user_id SERIAL PRIMARY KEY,

CREATE TABLE User_Problems (
    problem_id SERIAL PRIMARY KEY,
    user_id INTEGER REFERENCES Users(user_id) ON DELETE CASCADE,
    problem_name VARCHAR(255) NOT NULL, -- e.g., "diabetes"
    description TEXT, -- User-provided details
    embedding VECTOR(384), -- Vector embedding for semantic similarity (384 dims for common models like BERT)
    created_at TIMESTAMP DEFAULT CURRENT_TIMESTAMP

CREATE TABLE Remedies (
    remedy_id SERIAL PRIMARY KEY,
```

### Explanation of Key Features
1. **Partitioning (Chunks)**:
   - **User_Interactions** and **Recommendations** are partitioned by `created_at` (monthly chunks for 2025).
   - Benefits:
     - Improves query performance for large datasets.
     - Allows easy archival of old data.
     - Scalable for millions of interactions.
   - Example: Queries for January 2025 data only scan `User_Interactions_2025_01`.
   - To add new partitions:
     ```sql
     CREATE TABLE User_Interactions_2025_03 PARTITION OF User_Interactions
         FOR VALUES FROM ('2025-03-01') TO ('2025-04-01');
     ALTER TABLE User_Interactions_2025_03 ADD PRIMARY KEY (interaction_id);
     ```

2. **Vectors for Recommendations**:
   - **pgvector**: Stores 384-dimensional embeddings in `Remedies.embedding` and `User_Problems.embedding` (compatible with models like BERT or SentenceTransformers).
   - **Semantic Similarity**:
     - Compute cosine similarity between user problem embeddings and remedy embeddings.
     - Example query to find top 5 remedies for a user problem:
       ```sql
       SELECT r.remedy_id, r.title, r.description,
              (r.embedding <=> (SELECT embedding FROM User_Problems WHERE problem_id = 1)) AS distance
       FROM Remedies r
       ORDER BY distance ASC
       LIMIT 5;
       ```
     - `hnsw` indexes on `embedding` columns optimize vector searches.
   - **Embedding Generation**:
     - Use an external model (e.g., SentenceTransformers in Python) to generate embeddings for `description` (Remedies) and `description`/`problem_name` (User_Problems).
     - Example Python code (run separately):
       ```python
       from sentence_transformers import SentenceTransformer
       model = SentenceTransformer('all-MiniLM-L6-v2')  # 384 dims
       description = "Drink bitter gourd juice daily to manage blood sugar levels."
       embedding = model.encode(description).tolist()
       # Insert embedding into PostgreSQL
       ```
     - Update embeddings when remedies or problems are added/edited.

3. **Recommendation System**:
   - **Inputs**:
     - **User Problems**: `User_Problems.problem_name` and `embedding`.
     - **User Preferences**: `Users.preferences` (e.g., categories).
     - **Health Conditions**: `Users.health_conditions`.
     - **Interactions**: `User_Interactions` (views, likes, searches).
     - **Remedy Metadata**: `Remedies.tags`, `related_problems`, `embedding`.
   - **Algorithm**:
     - **Vector-Based (50%)**:
       - Use cosine similarity between `User_Problems.embedding` and `Remedies.embedding`.
       - Prioritize remedies with low vector distance (high similarity).
     - **Content-Based (30%)**:
       - Match `User_Problems.problem_name` to `Remedies.related_problems` or `tags`.
       - Example query:
         ```sql
         SELECT r.remedy_id, r.title
         FROM Remedies r
         WHERE r.related_problems @> ANY (
             SELECT jsonb_build_array(problem_name)
             FROM User_Problems
             WHERE user_id = 1
         );
         ```
     - **Collaborative Filtering (20%)**:
       - Find similar users via `User_Interactions` (e.g., users who liked similar remedies).
       - Recommend popular remedies among similar users.
       - Example query:
         ```sql
         SELECT r.remedy_id, r.title, COUNT(ui.interaction_id) AS interaction_count
         FROM Remedies r
         JOIN User_Interactions ui ON ui.content_type = 'remedy' AND ui.content_id = r.remedy_id
         WHERE ui.user_id IN (
             SELECT DISTINCT ui2.user_id
             FROM User_Interactions ui2
             WHERE ui2.content_type = 'remedy' AND ui2.content_id IN (
                 SELECT content_id
                 FROM User_Interactions
                 WHERE user_id = 1 AND content_type = 'remedy'
             )
             AND ui2.user_id != 1
         )
         GROUP BY r.remedy_id, r.title
         ORDER BY interaction_count DESC
         LIMIT 5;
         ```
     - **Hybrid Score**:
       - Combine scores (vector distance, tag overlap, interaction counts) into `Recommendations.score`.
       - Normalize to 0–1 (e.g., `score = 0.5 * (1 - vector_distance) + 0.3 * tag_match_score + 0.2 * interaction_score`).
   - **Implementation**:
     - Run a daily `node-cron` job to compute recommendations.
     - Store results in `Recommendations` table.
     - Cache in Redis (key: `recommendations:user:123`).
     - Real-time recommendations for new problems:
       ```sql
       SELECT r.remedy_id, r.title,
              (r.embedding <=> (SELECT embedding FROM User_Problems WHERE problem_id = :problem_id)) AS distance
       FROM Remedies r
       WHERE r.category IN (:user_preferences)
       ORDER BY distance ASC
       LIMIT 10;
       ```

4. **Indexes**:
   - **GIN**: For JSONB (`tags`, `related_problems`) and full-text search (`tsv`).
   - **hnsw**: For vector similarity searches (`embedding`).
   - **B-tree**: For primary keys and foreign keys (`user_id`, `remedy_id`).

### Usage Instructions
1. **Setup PostgreSQL**:
   - Install PostgreSQL (version 14+).
   - Install `pgvector`:
     ```bash
     sudo apt-get install postgresql-15-pgvector  # Ubuntu example
     ```
     or compile from source: https://github.com/pgvector/pgvector.
   - Create a database:
     ```bash
     createdb ayurveda_app
     ```
   - Connect to the database:
     ```bash
     psql -d ayurveda_app
     ```

2. **Execute SQL**:
   - Copy the SQL script above into a file (e.g., `ayurveda_data_model.sql`).
   - Run in PostgreSQL:
     ```bash
     psql -d ayurveda_app -f ayurveda_data_model.sql
     ```

3. **Generate Embeddings**:
   - Use a model like SentenceTransformers to generate 384-dimensional embeddings.
   - Example Python script (run separately):
     ```python
     from sentence_transformers import SentenceTransformer
     import psycopg2

     model = SentenceTransformer('all-MiniLM-L6-v2')
     conn = psycopg2.connect("dbname=ayurveda_app user=postgres password=your_password")
     cur = conn.cursor()

     # Update Remedies embeddings
     cur.execute("SELECT remedy_id, description FROM Remedies")
     for remedy_id, description in cur.fetchall():
         embedding = model.encode(description).tolist()
         cur.execute(
             "UPDATE Remedies SET embedding = %s WHERE remedy_id = %s",
             (embedding, remedy_id)
         )

     # Update User_Problems embeddings
     cur.execute("SELECT problem_id, description FROM User_Problems WHERE description IS NOT NULL")
     for problem_id, description in cur.fetchall():
         embedding = model.encode(description).tolist()
         cur.execute(
             "UPDATE User_Problems SET embedding = %s WHERE problem_id = %s",
             (embedding, problem_id)
         )

     conn.commit()
     cur.close()
     conn.close()
     ```
   - Install dependencies:
     ```bash
     pip install sentence-transformers psycopg2-binary
     ```

4. **API Integration**:
   - Use Sequelize (Node.js) to query the database.
   - Example endpoint for recommendations:
     ```javascript
     app.get('/api/recommendations/:user_id', async (req, res) => {
         const { user_id } = req.params;
         const recommendations = await sequelize.query(`
             SELECT r.remedy_id, r.title, rec.score
             FROM Recommendations rec
             JOIN Remedies r ON rec.remedy_id = r.remedy_id
             WHERE rec.user_id = :user_id
             ORDER BY rec.score DESC
             LIMIT 10
         `, {
             replacements: { user_id },
             type: sequelize.QueryTypes.SELECT
         });
         res.json(recommendations);
     });
     ```

5. **Front-End (React Native)**:

   - Fetch recommendations via API:
     ```javascript
     axios.get(`/api/recommendations/${userId}`).then(response => setRecommendations(response.data));
     ```

### Sample Recommendation Query
To get recommendations for a user based on their latest problem:
```sql
SELECT r.remedy_id, r.title, r.description,
       (r.embedding <=> (SELECT embedding FROM User_Problems WHERE user_id = 1 ORDER BY created_at DESC LIMIT 1)) AS distance
FROM Remedies r
WHERE r.category IN (
    SELECT jsonb_array_elements_text(preferences->'preferred_categories')
    FROM Users
    WHERE user_id = 1
)
ORDER BY distance ASC
LIMIT 10;
```
